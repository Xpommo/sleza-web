# Кабинет «Слеза Белый Сайт» в React — передача в новую сессию

Состояние на 23.09.2026 (вечер). Всё закоммичено и запушено: `master` (исходники) и `gh-pages`
(сборка в `anketa/`). MVP 1 (статичный макет) на gh-pages намеренно оставлен «до правок»
(16.09); его правки 16–18.09 — ветка `anketa-hierarchy` на origin. Прототип без бэкенда: вся логика в браузере, состояние —
анкета в `sessionStorage` (`start/_shared/anketaState.js`).

Живая ссылка: https://xpommo.github.io/sleza-web/anketa/app/register/
На каждом экране — панель **«Макет»** (правый нижний угол): 13 готовых состояний
и переходы на все экраны. Проверять руками — через неё.

## Главное правило

Пользователь: «берём только дизайн, логика остаётся». Логику, тексты и решения не
придумываем — переносим из утверждённого и сверяем. Много времени ушло на правки,
которые легко потерять.

Решения, которые легко сломать:
- **«Подписка» — в меню аккаунта** (`/app/billing`), не сайта (18.09). Но с 23.09 у
  каждого сайта **свой тариф, свой год подписки и своя дата продления**; общие —
  способ оплаты, карта, плательщик, почта для актов. Оплата, тариф и **отключение сайта —
  только в «Подписке»**, в строке сайта (на «Обзоре» кнопки нет). Подробно — ниже, в
  «Решениях владельца 23.09».
- Пробный период — **5 дней, стартует сам, когда код найден**; кнопки «Активировать» нет.
- Реквизиты правятся **только в «Документах»** (карандаш у «Реквизитов владельца»).
- После отключения/неоплаты уже опубликованные страницы документов **остаются доступны
  по ссылке** (24.08) — не писать «ссылки перестанут открываться».
- Шаг «Данные клиентов» **никогда не пропускается** (9.09).
- В кабинете нет слова «защита» и обещаний исхода проверки. Нет «Данные не передаём
  третьим лицам».
- Баннер cookie — без кнопки «Отклонить». Тема виджета одна на шаг 5 и «Виджет».
- Состояние подписки выводится только в `site/_shared/subscription.js`.

## Как проверять и публиковать

Проверочные сценарии Playwright — локально в `design-export/cabinet-checks/` (не в git):
`flow.mjs 1440|390` — весь путь с нуля до документов; `audit.mjs` — 20 экранов × 2
ширины (ошибки, скролл, поля без подписи; отчёт в `audit/report.json`); `single.mjs` и
`multi2.mjs` — «Подписка» одного и нескольких сайтов; `d.mjs` — «Документы». Ждут
сборку в `/tmp/srv/sleza-web/anketa` и `python3 -m http.server 8899` в `/tmp/srv`. Пути
к скриншотам внутри — в скретчпад прошлой сессии, поправьте переменную `O`/`OUT`.
Два «✗» в `flow.mjs` ложные: «нет чужого cookie-баннера» (находит слово cookie в тексте
регистрации) и «имя в сайдбаре» на 390 (там имя в меню аватара).


```bash
cd frontend && export NVM_DIR="$HOME/.nvm" && source "$NVM_DIR/nvm.sh"
node scripts/build-ghpages.mjs                      # статическая сборка в frontend/out
cp -R out /tmp/srv/sleza-web/anketa                 # локально: python3 -m http.server 8899 в /tmp/srv
# публикация: worktree ветки gh-pages в /tmp/ghp → rm -rf anketa && cp -R ../frontend/out anketa → commit → push
```
Playwright — `backend/node_modules/playwright/index.mjs`. Проверять сценарием, а не
глазами: переходы, состояния, F5/«Назад», ширины 390/1024/1440, ошибки консоли.
`master` не пушить без просьбы (Vercel деплоит с него). `gh-pages` — пушим.

Выгрузка экрана макета (`/tmp/scr.sh`):
```bash
F=/tmp/mvp2.html; git show anketa-hierarchy:cabinet-mvp.html > $F
s=$(grep -n "id=\"$1\"" "$F" | head -1 | cut -d: -f1)
e=$(awk -v s=$s 'NR>s && /id="s-[a-z0-9-]+"/ && /<(section|div|main)/{print NR; exit}' "$F")
awk -v a=$s -v b=${e:-$((s+600))} 'NR>=a && NR<b' "$F" | sed -E 's/<!--/\x01/g; s/-->/\x02/g' | tr '\n' ' ' \
 | sed -E 's/\x01([^\x02]*)\x02/\n    ⟦\1⟧\n/g; s/<[^>]*>/\n/g; s/[ \t]+/ /g' | grep -v '^\s*$'
```
