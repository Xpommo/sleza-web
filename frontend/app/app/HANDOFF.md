# Кабинет «Слеза Белый Сайт» в React — передача в новую сессию

Состояние на 22.09.2026. Прототип без бэкенда: вся логика в браузере, состояние —
анкета в `sessionStorage` (`start/_shared/anketaState.js`).

Живая ссылка: https://xpommo.github.io/sleza-web/anketa/app/register/
На каждом экране — панель **«Макет»** (правый нижний угол): 13 готовых состояний
и переходы на все экраны. Проверять руками — через неё.

## Главное правило

Пользователь: «берём только дизайн, логика остаётся». Логику, тексты и решения не
придумываем — переносим из утверждённого и сверяем. Много времени ушло на правки,
которые легко потерять.

## Чего нет — сделать в новом дизайне, логика из живого макета

1. **Вход в кабинет** — `s-login`. Сейчас «Войти» ведёт на `/app/login` в старом дизайне
   (`login/LoginClient.js`). Telegram / MAX / почта, «Нет аккаунта? Создать», ссылки
   «Политика · Оферта».
2. **Вход по почте** — `s-maillogin`: почта → «Прислать код» → «Проверьте почту», код 6
   цифр, 30 минут. Из FIXLOG: вход по почте не должен обнулять аккаунт (интент в
   `mailFlow`). ⚠ Спросить пользователя: на регистрации «Через почту» у нас сразу
   пускает в кабинет, в макете ведёт сюда. Это не то подтверждение почты, которое сняли
   на шаге 1, но уточнить.
3. **Настройки** — `s-settings`: «Ваши контакты и вход в кабинет — общие для всех
   сайтов». Сводки с «Изменить», без пароля. «← Назад» возвращает туда, откуда пришли.
4. **Меню аккаунта** на аватаре (Настройки / Поддержка / Выйти) — во всех сайдбарах
   (`SidebarShell` в `SiteChrome.js` и `Sidebar` в `start/_shared/AnketaChrome.js`).
   «Выйти» не должно быть мёртвым (FIXLOG, коммит d736f60).
5. Окна: `modal-no-script` («Пока не видим скрипт» → «Проверить ещё раз / Написать в
   поддержку», текст с доменом) вместо нашего «Понятно» в `start/code/CodeClient.js`;
   `modal-req-invoice` (9 полей плательщика) вместо трёх полей в `billing/BillingClient.js`.
6. Подписи статусов карточки в «Моих сайтах» свести с `s-status` (у нас свои).
7. Мобильный: в макете таббар сайта и лист «Ещё» — сверить, у нас сайдбар сверху.

  Блокер запуска. `/privacy` — политика сканера «Фонарик», не подходит.
- Не сказано до оплаты картой, что через год спишется 12 000 ₽.
- GA на шаге 2: «предупредим о рисках» ничем не подкреплено.
- Маркировка наркотических веществ упомянута только в пилюле подвала.
- «Добавить сайт» при существующем сайте открывает его же анкету (прототип держит один
  сайт).
- Правки анкеты из переписки не перенесены в живой макет — перенести или считать код
  источником.
- Фирменный синий: в коде токен `brand` #1f1fe6; пользователь в задании назвал #3157d5.

## Как проверять и публиковать

```bash
cd frontend && export NVM_DIR="$HOME/.nvm" && source "$NVM_DIR/nvm.sh"
node scripts/build-ghpages.mjs                      # статическая сборка в frontend/out
cp -R out /tmp/srv/sleza-web/anketa                 # локально: python3 -m http.server 8899 в /tmp/srv
# публикация: worktree ветки gh-pages в /tmp/ghp → rm -rf anketa && cp -R ../frontend/out anketa → commit → push
```
Playwright — `backend/node_modules/playwright/index.mjs`. Проверять сценарием, а не
глазами: переходы, состояния, F5/«Назад», ширины 390/1024/1440, ошибки консоли.
`master` не пушить без просьбы (Vercel деплоит с него). `gh-pages` — пушим.

Выгрузка экрана макета (`/tmp/scr.sh`):
```bash
F=/tmp/mvp2.html; git show anketa-hierarchy:cabinet-mvp.html > $F
s=$(grep -n "id=\"$1\"" "$F" | head -1 | cut -d: -f1)
e=$(awk -v s=$s 'NR>s && /id="s-[a-z0-9-]+"/ && /<(section|div|main)/{print NR; exit}' "$F")
awk -v a=$s -v b=${e:-$((s+600))} 'NR>=a && NR<b' "$F" | sed -E 's/<!--/\x01/g; s/-->/\x02/g' | tr '\n' ' ' \
 | sed -E 's/\x01([^\x02]*)\x02/\n    ⟦\1⟧\n/g; s/<[^>]*>/\n/g; s/[ \t]+/ /g' | grep -v '^\s*$'
```
